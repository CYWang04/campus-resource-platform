## 2026-10-21 前期实现选择（待团队评审）

用户已授权串行开发。当前实现沿用三个服务及数据库归属，具体选择如下，均不表示全组已接受：

- 首版使用 JdbcTemplate 与显式 SQL 事务/行锁，便于检查来源版本和数据库边界；未引入 JPA 自动建表。后续如引入 JPA，仍须保持 Flyway 所有权。
- 自建账号使用 BCrypt 密码摘要、随机会话令牌及 SHA-256 会话摘要；随机本地密码不入库之外的版本管理。
- 工单命令返回 HTTP 200 与已保存的当前工单视图；START_PENDING/RELEASE_PENDING 明确为处理中，通过工单详情的 operations 查询同步结果。这是对 INTERFACES 中异步 202 方案的前期调整，尚未冻结为完整业务契约。
- 首版仅开放 M3_MAINTENANCE 来源、教室级维修限制，不接受 M2 占用。M2 占用、预约取消和终态保护仍待对应业务实现。共享服务凭证仅用于本地前期，接入更多内部写调用前需按调用方拆分。
- 最小工单采用报修→维修人员直接开始→完工→管理员验收；正式派单、超时升级、评价后续实现。
- 命令幂等键作用域为用户+键；来源操作按 operationId 去重，记录与来源墓碑保留至数据库重置。重复请求返回当前工单视图；内部历史结果另带 currentSourceState，避免误用历史生效状态。

## 2026-10-21 M2/M3 增量实现选择（待团队评审）

下列实现替代本页上一节中“维修人员直接开始”和“仅开放 M3 来源”的前期限制：

- M2 使用 `DEPARTMENT_PENDING → RESOURCE_PENDING → RESOURCE_SYNC_PENDING → APPROVED` 两级审批状态；最终批准前不占用教室，由 M1 锁定教室并检查资源版本、个人预约、维修和其他整室占用。
- M1 开放 `M2_ROOM_APPLICATION` 时段来源及 `M3_MAINTENANCE` 维修来源。整室批准和撤销使用持久化同步任务与来源版本，不直接跨库写入。
- M3 使用 `REPORTED → ASSIGNED → START_PENDING → REPAIRING → AWAITING_ACCEPTANCE → RELEASE_PENDING → CLOSED` 主状态链；管理员派单，指定维修人员处理，管理员可验收退回，报修人可在关闭后评价。
- 24/48 小时升级由 M3 定时扫描持久化时间字段实现。维修取消个人预约和已批准整室申请仍是后续一致性任务。

关联代码与机器可读子集见 [实现记录](IMPLEMENTATION.md)、[OpenAPI](../contracts/foundation.openapi.json)。P01～P14 的团队评审状态保持不变。

## 2026-10-29 M2 维修取消接收端（待评审）

- 沿用 U08，实现 M2 内部取消事件接收，新增 `CANCELLED_MAINTENANCE` 终态；只取消已批准、资源批准同步中和撤销同步中的申请，不改写其他业务终态。
- 事件收据、状态、审计和通知任务在同一事务内保存。相同事件 ID 不同内容返回 409；通知按申请只创建一次，使用原事件键投递 M3。
- 同步结果与取消均按“先锁申请、再锁任务”的顺序处理；取消后未完成任务标记 `SUPERSEDED`，迟到结果不得恢复申请。M1 的来源终态及历史操作响应仍需 M1 侧保证。
- 接收端沿用现有共享服务凭证；这不等于已实现逐调用方凭证隔离。新增 M2 V3 迁移，不修改 V1/V2。H2 仅作测试依赖，不替换 MySQL。

## 2026-10-26 M1 完善实现选择（待受影响组评审）

以下补充替代旧记录中“维修取消待实现”的状态；没有团队评审或人工验收通过记录。

- 单次上限默认 4 小时、可提前 7 天，分别允许管理员配置为 1～12 小时和 1～30 天。配置使用版本控制防止覆盖，持久化于 M1；新建及历史复用采用当前值，已有预约保留原时段。签到窗口固定为 `[开始, 开始+15分钟)`。
- 每日教室码只允许 `resources:manage` 读取并在管理端展示。学生手动输入现场码，不能从业务 API 自行取码；独立屏幕身份尚未接入。每日码仍可能被转发，不能据此保证物理到场。
- M1 对同一教室先加行锁，资源写入采用 READ COMMITTED；个人预约、整室占用、维修和资源调整遵循相同锁顺序。幂等重放先核对操作指纹，首次请求才检查当前时间和资源版本。
- 维修影响尚未结束的 CONFIRMED/CHECKED_IN 个人预约及有效 M2 时段占用。个人预约取消、不记违约；M2 来源保存 CANCELLED 终态及维修原因，同一申请不能通过更高来源版本重新激活。解除维修后须重新申请。
- M1 同事务保存取消事件，通过真实 HTTP 持久化重试至 M2。M2 去重收件、取消同步任务、保护终态并保存通知任务；收到旧的批准回包时检查 `currentSourceState`。M1 先决定资源状态，M2 页面允许短暂滞后。
- 空院系归一为 NULL；座位所属教室不可直接移动，需新建座位并停用旧座位。停用、缩短开放时间或缩窄院系范围会影响有效个人预约/整室占用时拒绝。规则变化推进资源版本。
- 统计按预约开始日期及上海小时归集；结束的 CHECKED_IN 在查询层派生为 COMPLETED，数据库原状态保留。有效预约时长不计 CANCELLED、CANCELLED_MAINTENANCE、NO_SHOW；该值不是出勤时长或利用率。
- 内部仍共享本地服务密钥，尚未实现按调用方隔离；本轮不将此标为生产鉴权完成。接口、M1 V5/M2 V3 迁移及取消状态需 M1/M2 和受影响的 M3 共同评审。

实际验证与明确限制见 [M1_ITERATION_1](M1_ITERATION_1.md)。
