# 规模与投入估算

更新日期：2026-10-20。本页保存规划对话中的工程估计，不是实际代码统计、教师指标或完成承诺。当前尚无应用代码。

前提：六人、统一 Vue/Java、三个业务服务、范围稳定、持续使用 AI 辅助且成员人工验收。每人天按 **6 小时有效投入**。

## 正式分工前

按 [FOUNDATION](FOUNDATION.md) 范围，约 4,000～7,000 有效行，其中前后端实现约 3,000～4,500，其余是测试和配置。分项为约数：

| 部分 | 行数估计 |
| --- | ---: |
| 前端公共骨架 | 600～1,000 |
| 后端公共基础 | 900～1,500 |
| 资源与数据基础 | 800～1,200 |
| 最小维修链路 | 400～700 |
| 自动化测试 | 700～1,200 |
| 迁移、契约及部署配置 | 500～1,000 |

分项相加约 3,900～6,600，整体按 4,000～7,000 留量。前期投入约 **8～12 人天**；5,000 行只是参考，不应为凑数扩功能。

早期估计的“12～18 人天公共基础”包含更完整的公共层完善；之后将正式分工前范围收敛，当前以前述 8～12 人天为准。后续公共层完善仍计入全项目，不重复累加。

口径包括手工维护的测试、SQL、YAML/配置；排除文档、空行、纯注释、依赖、自动生成代码及构建产物。前期骨架属于总量的一部分，不能在总量上再次相加。

| 工作 | 人天 |
| --- | ---: |
| 需求、架构、接口设计 | 4～6 |
| 公共骨架与公共能力 | 8～12 |

| M2 | 5～7 |

加入约 20% 缓冲，按 **60～85 人天，即 360～510 小时**排期。六人平均每人约 60～85 小时；若每人每周稳定投入 8～12 小时，约按 6～10 周安排。这是投入换算，课程截止日期尚未明确，不代表尚有这么长可用时间。

最大的估算风险是跨模块一致性、权限与定时任务、真实邮件/云部署、协作返工及 Agent 接入。公共基础验收后根据真实进度重新估计，不以代码行数判断质量或个人贡献。
