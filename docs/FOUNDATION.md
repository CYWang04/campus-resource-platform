## 最小链路

登录 → 查看教室座位 → 将简化工单切换为维修中 → M3 真实 HTTP 调用 M1 → M1 保存维修来源并下架 → 页面刷新展示不可用 → 验收通过 → 按该工单来源解除 → 展示可用性。

使用真实数据库与服务端权限，页面可以简单，工单流转可只实现本链路需要的部分并注明简化范围。验证：同请求重复发送不重复产生限制；同室两维修来源解除一项仍不可用；普通用户不能调用管理动作；发生依赖失败时不展示虚假成功。

## 开始正式分工的六项共同验收

- [ ] 任意成员按仓库说明可启动全套本地系统并重建演示数据。
- [ ] 普通用户与管理用户登录后，服务端权限差异实际生效。
- [ ] 三模块使用相同用户/教室/座位标识、时间与错误格式，公共接口有可用契约与示例。
- [ ] 维修链路从页面到跨服务写入再回到页面完整运行，重复和多来源解除检查通过。
- [ ] 新成员可照样例增加一个页面、接口和迁移，知道如何检查与提交。
- [ ] 公共能力有负责人，业务组理解数据边界、接口依赖和变更评审规则，已有基础自动检查。

通过后评审一份 `foundation-v0.1` 基线；是否创建 tag 由明确的版本操作任务执行。验收记录要含环境、步骤、结果、版本、问题与接受例外，勾选必须有证据。
