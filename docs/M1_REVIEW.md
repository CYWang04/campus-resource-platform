## 3. 优先修复清单

以下是核查结论及建议任务，均尚未实现。P1 表示优先修复，P2 表示后续完善；跨模块、公共层和 schema 变更仍需受影响组评审。

### M1-R01 / P1：先修复自动检查的时间数据

- 证据：[smoke.mjs](../scripts/smoke.mjs) 第 58–64、118 行使用运行机本地时区计算起点，然后对同一起点追加 9、10 小时；业务按上海时区校验 07:00–23:00。只改 `TZ` 也不能保证所有偏移都在开放时段。
- 本轮新建 M1 分支触发的 [Actions 40282859593](https://github.com/CYWang04/campus-resource-platform/actions/runs/40282859593) 中，Maven verify、前端构建、容器启动成功，smoke 第 118 行因 `POST /reservations: OUTSIDE_OPEN_HOURS` 失败，resilience 被跳过。
- 已在本机执行原脚本时间片段的独立复现：历史失败时刻 `2026-10-24T07:10:14Z` 在 UTC 运行机生成上海时间次日 03:00–04:00 的预约，确实超出开放时间。此复现不等同于本机 HTTP 集成测试。
- 建议：明确上海业务日期，给每组用例生成独立、未来且在开放时间内的时段，避免统一起点不断加偏移。
- 验收：在 UTC、Asia/Shanghai 两种运行时区及不同时刻均生成有效测试数据；smoke 与 resilience 全部运行通过。

### M1-R02 / P1：恢复“到教室后输入编码”的签到流程

- 证据：Resources.java 第 95–96 行仅要求 `resources:read` 就返回当天明文码；普通学生拥有该权限。Reservations.vue 第 109–110、265–268 行直接显示码，并可自动填入签到。
- 影响：学生在远处也能完成取码和签到，违约机制无法验证实际到场。
- 建议：取码限定教室屏幕/受控展示身份；学生端保留输入现场编码，移除自行取码和自动填码。展示凭证与普通学生权限如何区分，需与 M2 协调。
- 验收：学生调用展示接口被拒绝；输入正确现场码可签到；错误码、其他教室码、日期变更、窗口前后边界均验证。每日码仍可能被转发，应在验收和伦理分析中如实说明。

### M1-R03 / P1：修复 M2 占用的幂等重试

- 证据：Resources.java 第 152–160 行在读取 operations 幂等记录之前检查资源版本；第 207–208 行成功后又递增版本。
- 影响：M1 已成功占用但响应丢失时，相同 operationId 和请求内容再次提交，会因旧 expectedAvailabilityVersion 被拒绝。M2 的 [ApplicationWorker.java](../backend/m2/src/main/java/cn/edu/fudan/campus/m2/ApplicationWorker.java) 第 22–24 行将 4xx 归为失败，可能出现 M2 显示冲突、M1 实际仍占用。
- 建议：同操作的重放先核对指纹并返回历史结果和当前来源状态；首次操作才做资源前置条件检查。M2 应解析当前来源状态，不能只接受空响应成功。
- 验收：模拟响应丢失、重复请求、其他来源版本变化、解除后的旧请求；不重复占用，业务状态和实际资源最终一致。

### M1-R04 / P1：完成维修优先的取消闭环

- 证据：Resources.java 第 202–205 行只取消 `CONFIRMED` 个人预约；未处理仍有效的 `CHECKED_IN` 预约，也未使已批准的 M2 来源失效、保存可靠回调任务或通知 M2 取消申请。
- 影响：M2 仍可能显示 APPROVED；维修解除后原整室占用继续有效，与 DECISIONS U08 的“取消后重新申请”不符。
- 建议：按 U07/U08 和待评审的 P08 明确受影响范围；M1 本地事务撤销相关占用、保存取消事件；M2 幂等接收并保护取消终态。故障恢复及迟到批准回包不得使同一申请复活。
- 验收：个人待签到/已签到、已批准/同步中的整室申请、多张维修工单、回调失败重试、维修解除、迟到回包全部覆盖；因维修取消不记学生违约。

### M1-R05 / P1：实现预约时长配置

- 证据：Reservations.java 第 17、197–202 行固定最大 4 小时；Reservations.vue 第 111、175、210 行也固定 4。当前没有对应配置表或管理接口。
- 影响：只满足默认 4 小时，没有满足 R-M1-03 的“系统参数可调”。
- 建议：定义配置读取、修改权限、生效规则和历史预约处理；前端读取有效配置，不重复写死。7 天预约窗口属于项目参数，也可同时统一来源。
- 验收：管理员将上限改为 2/6 小时后，前后端一致；越界请求被拒绝；重启后配置保留，已有预约按明确规则处理。

### M1-R06 / P1：补齐资源变更保护与全校开放语义

- 证据：Resources.java 第 101 行只在停用时检查个人预约，缩短开放时间/更换院系不会检查存量预约；第 103 行允许直接把已有预约的座位移动到另一教室。停用检查也未覆盖 M2 有效整室占用。
- 另外，M1Admin.vue 提示“院系留空表示全部院系”，实际提交空字符串；后端直接保存，查询却只把 `NULL` 当作全校开放，新建教室可能对正常学生不可见。
- 建议：统一空院系为 NULL；资源调整前检查全部受影响业务，禁止隐式破坏历史和有效预约；座位迁移应禁止或采用有记录的专门流程。补管理员查看、编辑、启停页面。
- 验收：有个人预约/整室占用时修改规则得到明确拒绝或按批准流程处理；历史地点不随座位改动而混乱；留空院系创建后各院系学生可见。

### M1-R07 / P1：统一查询与最终预约的可用性规则

- 证据：Resources.java 第 53–92 行座位详情只查资源限制与重叠预约，没有执行教室启用、院系、开放时段检查；个人创建接口在 Reservations.java 第 59–62 行才执行这些检查。
- 影响：可以查询到标记 `available=true`、但实际不能预约的座位；绕过列表直接访问 ID 时，院系资源读取规则也不一致。M2 新增占用的 M1 接口同样缺少教室启用和开放时段保护。
- 建议：共用明确的可用性判定，返回具体原因；列表、详情和写操作保持一致，写入仍在事务内重查。联合 M2 明确整室预约适用的开放规则。
- 验收：停用、跨院系、开放前后、个人占用、M2 占用、维修均得到一致查询结果；并发期间的失效选择返回明确冲突。

### M1-R08 / P1：补 M1 自动测试与真实页面验收

- 证据：仓库没有 M1 的 `src/test` 测试；当前 Maven 的两个测试均属于 M3。已有真实 smoke 覆盖部分预约行为，但当前流水线提前失败，后续断言并未执行。前端 package.json 没有测试命令。
- 建议：对 R02–R07 的行为补回归测试；采用真实 MySQL 验证锁、事务和并发，使用可控制时钟验证提醒/违约；页面走通资源筛选、预约、手动签到、取消、历史复用、管理和统计。
- 验收：同座位并发仅一人成功，个人预约与整室审批不双占，多来源解除不误恢复，重复任务不重复处罚，故意破坏关键判断时测试失败。

### M1-R09 / P2：完善搜索、管理与历史页面

- 当前楼宇/插座参数在后端存在，Rooms.vue 和 Reservations.vue 均未提供对应筛选控件；不能把下拉项展示插座类型当作已经支持条件搜索。
- 管理页面主要能新增资源，缺少完整列表、编辑、启停和停用资源查看。学生预约只读取前 100 条历史，没有分页控件。

### M1-R10 / P2：补幂等、时间和通知的边界

- Reservations.java 第 47–50 行先校验“开始时间在未来”，再读取历史命令；创建已成功但响应丢失、重试时已到开始时间，会返回 START_IN_PAST。
- 第 118 行签到允许精确第 15 分钟，ReservationWorker 第 22 行同时把该时点视为逾期；需统一为明确的半开窗口。整点校验也应拒绝非零纳秒。
- ReservationWorker 的通知投递缺少显式连接/读取超时和失败查看入口，恢复后补发提醒时也未重读预约是否已取消/签到。
- 验收：跨开始时刻仍可重放同一创建结果；15 分钟边界唯一；服务恢复后不发失效提醒，重试可追踪且不重复处罚。

### M1-R11 / P2：补运营与审计

- 统计当前主要是数量，`HOUR(start_at)` 直接按 UTC 数据分组；若界面按上海小时展示，需要明确转换。补日期/教室筛选、预约时长、利用率与管理员明细。
- M1 当前迁移和写操作中没有与 M2/M3 类似的本地业务审计链路；资源编辑、预约取消、签到、自动处罚应可追溯操作者、原因、requestId 和业务来源。
- 已签到预约没有明确“已结束”状态或历史展示归类，可先在查询/页面按结束时间派生，避免直接扩大状态机。
- 验收：统计口径和时间区一致；管理员能够解释某座位为何不可用及某次处罚的形成过程。

### M1-R12 / P2：完善开发交接和性能

- 当前启动/初始化指南主要面向 Windows PowerShell；本次接手环境为 macOS，缺少通用 shell 初始化和检查入口。
- 前端入口同步导入全部页面并全量引入 Element Plus；本轮远端构建主 JS 为约 1,018 kB，存在大包警告。可按路由拆包、按需引入。

- 验收：新成员在 macOS/Linux 可照文档启动；优化前后保留相同业务行为，并提供构建体积或查询次数对比。
