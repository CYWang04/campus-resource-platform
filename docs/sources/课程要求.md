# 软件过程管理与工程伦理：课程要求

> 课程代码：EIE60029  
> 学分与学时：3 学分，54 学时（含实践 27 学时）  
> 课程性质：专业学位研究生必修课  
> 整理依据：课程介绍、第一讲课件、Lab1 说明及课堂照片。未明确事项以 eLearning 和教师后续通知为准。

## 1. 课程形式

- 课堂讲授；
- 课堂小组讨论与 Review；
- 小组项目实践：围绕给定项目完成功能实现、扩展和维护；
- 个人作业共 2 次，其中包含课程论文；
- 项目进展汇报、成果展示与讨论。

课程强调理论与工程实践结合，理论学时与实践学时各占一半，并将工程伦理贯穿需求、开发、测试和交付等环节。

## 3. 小组实践项目要求

### 3.1 组队与分工

- 每组 3～6 人，最多不超过 6 人；
- 每组选出 1 名组长；
- Lab 共包含 3 个模块，要求成员分工协作完成；
- 分组基本确定后，同组成员加入同一个项目；
- 需要参加项目进展汇报、展示和讨论。

### 3.2 平台与环境

- 华为为每组提供 2 台云服务器；
- 使用华为云码道（CodeArts）托管代码；
- 建立部署流水线；
- 发布测试环境和生产环境；
- 开通华为云码道代码智能体；
- 建议使用 Docker；
- 前期需要熟悉华为云码道，各自创建项目并熟悉平台功能。

### 3.3 重点考察内容

- 需求的获取与整理；
- 任务分解与任务追踪；
- 自动化测试；
- 人工验证与自动化验证的结合；
- 自动化部署；
- 系统维护与升级；
- 大模型或 Coding Agent 在软件过程中的使用；
- 项目各阶段的责任、风险和工程伦理问题。

项目考核不仅关注最终功能，还关注需求、任务、提交、测试、部署、协作和改进过程是否完整、规范、可追踪。

## 4. 个人实验一（Lab1）要求

### 4.1 实验任务

从 Git 提交历史分析 `deepseek-harness` 的开发过程。实验为个人任务，应借助 AI 编程助手完成分析，但最终结论、判断和报告必须由本人负责。

### 4.2 交付物

- 独立提交 1 份 Markdown 说明文档；
- 建议文件名为 `分析报告.md`；
- 严格按照以下 6 个问题组织章节。

### 4.3 六个必答问题

1. 开发周期、提交频率与团队组成；
2. AI Coding 的大致密度，并给出量化估计和判断依据；
3. 是否存在分支合并、代码冲突及冲突解决；
4. 项目文档主要面向人类读者还是面向 AI Agent；
5. 能否从 Git 历史识别需求、设计、开发和测试过程；
6. 其他有代表性的过程现象，并联系过程模型、质量门禁、可重复性、配置管理等课程概念进行点评。

### 4.4 报告内容要求

每一题均应包含：

- 明确结论；
- 数据或原始证据；
- 分析与论证；
- 对 AI 分析方法可信度的判断。

报告还应附上 AI 助手给出的关键分析输出，例如命令结果、数据表和图表，使主要统计数字能够复现。

### 4.5 禁止事项

- 不得直接复制他人报告；
- 不得原样照搬 AI 输出而没有个人判断和标注；
- 所有统计数字必须来自实际分析结果；
- 不得只给结论而缺少证据和复现材料。

## 5. 课程论文要求

### 5.1 已明确的基本要求

- 题目自拟；
- 内容详实；
- 有主动思考；
- 格式规范；
- 字数不限；
- 结合课程理论学习和项目实践；
- 阐述对当代软件开发中过程管理要点的理解与体会。

论文不宜写成单纯的概念综述，应包含个人或团队项目中的实际过程、证据、问题分析和改进反思。

### 5.2 教师建议的主题方向

教师建议以“过程改进”为主题，将过程改进本身作为一个独立过程进行研究：

1. 采集真实的软件过程数据；
2. 分析当前过程及其问题；
3. 制定改进目标和措施；
4. 实施或设计改进方案；
5. 使用指标验证改进效果；
6. 总结局限与后续改进方向。

可使用的课程方法包括：

- PDCA；
- IDEAL；
- GQM；
- CMMI 相关度量方法。

### 5.3 推荐使用的项目证据

- 华为云码道中的需求和任务记录；
- Git 提交、分支和合并记录；
- 测试结果、覆盖情况和缺陷记录；
- 流水线执行情况；
- 部署、发布、维护和升级记录；
- 使用大模型或 Agent 的过程记录；
- 改进前后的指标变化。

### 5.4 智能化开发与工程伦理

论文可结合智能化开发带来的新过程，并融入以下工程伦理问题：

- 公平性；
- 隐私保护；
- 知识产权与开源许可证；
- AI 生成代码的来源和使用边界；
- 安全、质量与事故责任；
- 人是否能够将技术决策责任委托给 AI；
- AI 输出的验证、记录和追责机制。

现有课程介绍使用“可融入工程伦理考量”的表述，因此工程伦理属于强烈建议方向；是否必须设置独立章节，现有材料尚未明确。

### 5.5 推荐论文结构

1. 引言：项目背景、研究问题和论文目标；
2. 理论基础：敏捷、Scrum、DevOps、PDCA、IDEAL 等；
3. 项目过程现状：需求、任务、开发、测试和部署流程；
4. 数据与问题诊断：使用真实记录证明问题；
5. 改进方案：措施、责任人、实施步骤和评价指标；
6. 改进效果或验证方案：改进前后对比；
7. AI 使用与工程伦理分析；
8. 个人反思：有效经验、失败原因和局限性；
9. 结论。

推荐选题形式：

> 一个具体项目 + 一个明确的过程问题 + 一套改进方法 + 可验证的指标 + 工程伦理反思

示例：`基于 PDCA 的 AI 辅助软件项目测试过程改进研究——以课程实践项目为例`。
